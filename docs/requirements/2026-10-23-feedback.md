# 意见反馈

登录用户从「我的 → 意见反馈」进入 `/profile/feedback`。页面包含返回按钮、标题、反馈文本域、字符计数和「提交反馈」按钮，不显示底部 Tabbar。

内容去除首尾空白后须为 1–1000 个 Unicode 码点，中文和单码点 emoji 均计为一个字符。空白或超长时显示说明并禁用提交。提交期间禁用文本域和按钮，显示「提交中…」，同步锁防止连续点击产生重复请求。按钮位于文本域下方，页面可滚动并预留安全区域。

成功后提示「反馈已提交，感谢你的建议」，以替换历史记录的方式返回 `/profile`；失败时提示接口错误或重试信息，保留内容并允许重试。离开页面丢弃未提交内容，不持久化草稿。

## 接口与存储

`POST /api/feedbacks`，要求有效的 Bearer 访问令牌，请求体仅允许 `{ "content": "反馈内容" }`。用户 ID 从认证上下文获取，客户端提交 `userId` 或其他额外字段会被拒绝。服务端按相同规则校验并去除首尾空白后保存。

成功返回 HTTP 201：

```json
{ "success": true, "data": { "id": 1 }, "message": "请求成功" }
```

校验失败沿用全局异常处理的 HTTP 200 与 `success: false`；未登录返回 HTTP 401；保存失败返回 HTTP 500，错误消息不暴露数据库细节。

`feedbacks` 表复用基础实体的整数 ID、创建时间、更新时间及软删除字段，增加 `userId`、`content VARCHAR(1000)`、用户外键和 `(userId, createdAt)` 索引，使用 `utf8mb4`。初始化脚本与 `kethe-backend/sql/2026-10-23-feedbacks.sql` 保持一致；发布时先执行建表脚本，再部署接口与页面。

本期不包含图片、联系方式、反馈列表、处理状态、管理后台或邮件通知。

## 验收

- 自动测试覆盖保存、用户归属、非法字段与类型、空白、长度边界、中文与 emoji、认证失败及数据库失败；HTTP 测试使用实际认证守卫和统一响应包装。
- 手动检查入口与返回、连续提交、成功跳转、失败保留内容，以及移动设备软键盘和安全区域。
