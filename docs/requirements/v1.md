# 记账 H5 产品方案

## 1. 文档说明

- 产品形态：移动端 H5 记账产品
- 方案版本：v1.0
- 核心目标：提供快速记账、流水查询、收支分析和账户管理能力

## 2. 产品定位

产品定位为轻量、快速、清晰的个人记账工具，重点解决以下问题：

- 快速记录日常收入和支出。
- 按时间、分类和账户查询历史流水。
- 通过图表了解收支趋势和消费构成。
- 按月查看收入、支出和结余。
- 管理支出分类和资金账户。

首版应优先保证记账效率和统计准确性，避免因类型过多导致操作复杂或账务口径不一致。

## 3. 信息架构

底部设置 5 个 Tab：

1. 首页
2. 图表
3. 记账
4. 账单
5. 我的

「记账」建议设计为底部中间突出的圆形按钮。点击后进入二级记账页面，不设置独立的一级内容页。

```text
首页
├── 流水页
│   ├── 搜索页
│   └── 记账页
├── 图表
├── 记账页
├── 账单
│   └── 月度账单详情
└── 我的
    ├── 个人资料
    ├── 分类设置
    └── 账户设置
```

## 4. 功能方案

### 4.1 首页

#### 4.1.1 月度概览

首页顶部展示：

- 本月支出
- 本月收入
- 本月结余

本月结余的计算公式为：

```text
本月结余 = 本月收入 - 本月支出
```

建议突出显示本月支出，将收入和结余作为辅助信息。点击对应金额后，进入带有相应筛选条件的流水页。首页固定展示按上海时区计算的当前自然月数据，不提供月份选择器；查看历史月份统一从账单页进入。首页概览接口不接收月份参数，由服务端确定当前月份。

#### 4.1.2 今日与本周统计

使用两张样式一致的统计卡片，分别展示今日和本周的收入、支出：

```text
今日
支出 ¥128.00    收入 ¥500.00

本周
支出 ¥860.00    收入 ¥2,500.00
```

与上一周期的环比数据可作为后续版本能力，首版不建议展示。

#### 4.1.3 最近流水

展示全部账户中最近 10 条流水，并按日期分组：

```text
今天 08 月 30 日              支出 ¥68.00
餐饮 · 午餐                    -¥38.00
交通 · 地铁                    -¥30.00

昨天 08 月 29 日              收入 ¥500.00
工资                           +¥500.00
```

每条流水建议展示：

- 分类图标
- 一级分类和二级分类
- 备注；没有备注时显示分类名称
- 账户
- 记账时间
- 金额
- 流水类型

最近流水区域仅用于数据展示，不提供账户筛选或其他筛选条件，首页概览接口也不接收账户筛选参数。列表底部提供「查看更多流水」按钮，点击进入流水页；筛选操作统一在流水页完成。没有数据时展示空状态和「记一笔」按钮。

### 4.2 流水页

#### 4.2.1 顶部操作

- 左侧展示页面标题「流水」。
- 右侧展示搜索图标和新增图标。
- 搜索图标进入搜索页。
- 新增图标进入记账页。
- 建议增加筛选入口。

#### 4.2.2 筛选能力

建议支持以下条件：

- 日期范围
- 流水类型
- 分类
- 账户
- 金额范围

#### 4.2.3 流水列表

流水默认按日期倒序并按天分组，每个日期分组显示当日收入和支出汇总。列表采用分页或下拉加载，避免一次加载全部数据。

用户可以点击流水进入编辑页面。删除操作需要二次确认，并同步更新账户余额和统计数据。

#### 4.2.4 搜索页

搜索范围包括：

- 备注
- 分类名称
- 账户名称
- 金额

搜索结果继续按日期分组，并支持叠加日期、类型和账户筛选。

### 4.3 图表页

图表页默认展示条形图，支持切换为饼图。

#### 4.3.1 顶部筛选

- 时间维度：月、年、自定义时间范围
- 收支类型：支出、收入
- 账户

#### 4.3.2 条形图

条形图用于展示金额趋势：

- 月视图按日统计。
- 年视图按月统计。
- 点击柱体后显示对应日期和金额。

#### 4.3.3 饼图

饼图用于展示分类占比：

- 支出默认按一级分类统计。
- 点击一级分类后，可查看二级分类占比。
- 图表下方展示分类排行榜、金额和占比。

虽然原始需求中收入暂不分类，但收入没有分类会降低图表分析价值。建议首版为收入提供工资、奖金、兼职、理财、礼金和其他等一级分类，暂不提供二级分类。

### 4.4 账单页

账单页顶部左侧提供年份选择器，并展示当前年份的汇总数据：

- 本年收入
- 本年支出
- 本年结余

原始需求中的顶部本月汇总与下方月度列表存在信息重复，因此建议改为年度汇总。下方按月份展示：

| 月份 | 月收入 | 月支出 | 月结余 |
| --- | ---: | ---: | ---: |
| 8 月 | ¥5,000.00 | ¥3,200.00 | ¥1,800.00 |
| 7 月 | ¥6,000.00 | ¥4,100.00 | ¥1,900.00 |

点击月份进入月度账单详情，展示：

- 月收入、月支出和月结余
- 每日收支趋势
- 分类占比
- 当月流水列表

转账和余额调整不计入收入、支出及结余。

### 4.5 我的

页面展示：

- 用户头像
- 用户昵称
- 分类设置入口
- 账户设置入口

可在后续版本增加数据导出、主题设置、货币设置和关于产品等功能。

## 5. 记账页

### 5.1 类型设计

原始需求包含支出、收入、转账、余额、借贷、代付、报销和退款。如果全部平铺在顶部，会增加用户的理解和选择成本。

建议顶部一级类型设置为：

- 支出，默认选中
- 收入
- 转账
- 其他

「其他」中包含：

- 余额调整
- 借入
- 借出
- 代付
- 报销
- 退款

个人记账场景中支出频率通常最高，因此建议默认选择「支出」，并在后续记账时记住用户上一次选择的类型。

### 5.2 表单字段

记账表单包含：

1. 金额：必填，自动调起数字键盘。
2. 分类：支出和收入时必填。
3. 账户：必填，默认选择上次使用的账户。
4. 时间：默认当前时间，支持选择日期和切换到精确时刻，精度为时、分、秒。
5. 备注：选填。

金额输入框应位于页面视觉中心，页面底部固定「保存」按钮。保存成功后返回来源页面，并刷新相关统计和列表。

图片凭证和标签可作为后续版本功能。

### 5.3 类型与统计规则

| 类型 | 必填信息 | 统计及余额影响 |
| --- | --- | --- |
| 支出 | 金额、支出分类、付款账户 | 计入支出，扣减账户余额 |
| 收入 | 金额、收入分类、收款账户 | 计入收入，增加账户余额 |
| 转账 | 金额、转出账户、转入账户 | 不计入收支，调整两个账户余额 |
| 余额调整 | 账户、调整后余额 | 不计入收支，生成调整记录 |
| 借入 | 金额、收款账户、往来对象 | 增加账户余额，计入负债 |
| 借出 | 金额、付款账户、往来对象 | 扣减账户余额，计入债权 |
| 代付 | 金额、付款账户、往来对象 | 扣减账户余额，形成待收款 |
| 报销 | 原支出或金额、收款账户 | 冲减对应支出或单独统计 |
| 退款 | 原流水或金额、收款账户 | 冲减对应支出 |

报销和退款应支持关联原始支出，避免被统计为普通收入而造成统计失真。

## 6. 分类设置

分类设置页面顶部提供「支出」和「收入」切换。

### 6.1 支出分类

- 支持一级分类和二级分类。
- 提供餐饮、交通、购物、住房、娱乐、医疗等默认一级分类。
- 提供早餐、午餐、晚餐、公交、地铁等默认二级分类。
- 支持新增、编辑、排序和停用。
- 默认分类允许停用，不建议直接删除。

如果分类已经被流水使用，删除时应提示用户将其停用或将历史流水迁移至其他分类。

### 6.2 收入分类

提供一级分类，不设置二级分类。默认数据包括：

- 工资
- 奖金
- 兼职
- 理财
- 礼金
- 其他

## 7. 账户设置

### 7.1 账户分类

核心账户类型由后端固定枚举维护，不建立可动态增删的账户类型表。账户使用「一级类型 + 二级子类型 + 账户性质」描述：

| 一级类型 | 稳定编号 | 二级子类型及稳定编号 | 默认性质 |
| --- | ---: | --- | --- |
| 现金 | 1 | 无 | 资产（1） |
| 信用账户 | 10 | 信用卡（201）、消费信贷（202） | 负债（2） |
| 储蓄账户 | 20 | 借记卡（301）、存折（302） | 资产（1） |
| 虚拟账户 | 30 | 在线支付（401）、现金券（402）、储值卡（403） | 资产（1） |
| 其他 | 99 | 无 | 创建时选择资产（1）或负债（2） |

支付宝余额、微信零钱和 PayPal 等存在独立余额的服务归入「虚拟账户 / 在线支付」。花呗、京东白条等归入「信用账户 / 消费信贷」。支付渠道本身不等于余额账户，只有存在独立余额时才创建账户。

系统为新用户初始化以下默认账户：

| 名称 | 稳定标识 `systemKey` | 类型 |
| --- | --- | --- |
| 现金 | `cash` | 现金 |
| 储蓄卡 | `bank_card` | 储蓄账户 / 借记卡 |
| PayPal | `paypal` | 虚拟账户 / 在线支付 |
| 微信 | `wechat` | 虚拟账户 / 在线支付 |
| 支付宝 | `alipay` | 虚拟账户 / 在线支付 |

`systemKey` 用于保证默认账户初始化幂等。账户类型调整时不得修改已有 `systemKey`，也不得覆盖用户已经修改过的账户名称。

### 7.2 账户信息

账户信息包括：

- 账户名称、一级类型、二级子类型和账户性质
- 机构名称，可填写银行或服务商名称
- 账号后四位，仅信用卡、借记卡和存折支持，只保存四位数字，不保存完整卡号
- 信用额度，仅信用账户支持，使用最小货币单位的非负整数存储
- 初始余额、当前余额和币种
- 是否计入净资产
- 图标、排序、启用状态和备注

银行及服务商暂不单独建表，统一使用机构名称文本字段。首版币种固定为人民币，暂不实现账单日、还款日、现金券有效期和多币种扩展。

### 7.3 余额、欠款与净资产

- 资产账户余额使用正数。
- 信用等负债账户使用负余额表示欠款。
- 创建负债账户时，页面展示「初始欠款」并接收正数，提交时转换为负的初始余额。
- 信用账户的当前欠款不单独存储，始终按 `max(-currentBalance, 0)` 计算。
- 信用消费扣减信用账户余额，使负余额及欠款增加；退款增加余额，使欠款减少。
- 信用账户还款使用「资产账户 → 信用账户」的转账流水，不计入收入或支出。
- 信用额度和机构信息属于账户属性，不参与流水余额计算。
- 现金券默认不计入净资产，其他账户默认计入；信用账户作为负债参与净资产计算。

### 7.4 表单与校验

账户设置页面支持账户列表、新增和编辑。页面先加载已鉴权的 `GET /accounts/options` 元数据接口，再根据所选一级类型动态展示子类型、机构、账号后四位、信用额度和账户性质等字段。前端不得另外硬编码账户类型名称和类型关系，切换类型后不得提交已经隐藏的字段。

后端统一执行以下校验：

- 子类型必须属于所选一级类型，需要子类型的账户不得省略。
- 除「其他」外，账户性质由一级类型确定；「其他」创建时必须选择性质。
- 资产账户初始余额不能为负数，负债账户初始余额不能为正数。
- 信用额度只能由信用账户填写。
- 账号后四位只能由信用卡、借记卡和存折填写，且必须为四位数字。
- 类型或子类型变化时，清理不再适用的机构、后四位和信用额度等条件字段。

账户已有流水后，不允许修改一级类型、账户性质和初始余额；仍可修改同一一级类型下的子类型、账户名称、机构信息、净资产开关及备注。系统默认账户或已有流水的账户不能直接删除，应保留历史关联并通过停用处理。

### 7.5 API 约定

- `GET /accounts/options` 返回一级类型、子类型、默认性质以及表单字段能力，是前端账户表单的唯一配置来源。
- 创建和更新账户使用 `accountSubType`、`accountNature`、`institutionName`、`accountNumberLast4`、`creditLimit` 和 `includeInNetWorth` 字段。
- 账户响应返回上述属性，并增加只读字符串字段 `outstandingDebt`。
- 旧字段 `includeInAssets` 不再返回或接收，前后端统一使用 `includeInNetWorth`，本次升级不提供旧字段兼容层。
- 金额类 API 字段均使用最小货币单位的十进制整数字符串，避免 JavaScript 大整数和浮点数精度问题。

## 8. 核心业务规则

开发前需要统一以下规则：

1. 转账不属于收入或支出。
2. 余额调整不进入收支统计。
3. 退款优先冲减原支出，不作为普通收入。
4. 报销款优先冲减对应支出。
5. 删除流水后，需要同步恢复相关账户余额。
6. 修改金额、账户或类型后，需要重新计算相关账户余额和统计数据。
7. 分类和账户采用软删除，避免历史流水失效。
8. 金额使用最小货币单位的整数存储，例如人民币使用「分」，避免浮点数精度问题。
9. 每条流水分别保存创建时间、记账时间和更新时间。
10. H5 表单应自动保存本地草稿，防止误触返回或页面刷新造成数据丢失。
11. 账户欠款必须由当前余额实时计算，不保存可与余额产生冲突的独立欠款字段。
12. 资产账户向信用账户转账表示还款，转账前后只调整双方余额，不进入收支统计。
13. 默认账户初始化以 `systemKey` 判重，重复执行不得创建重复账户。

## 9. MVP 范围

### 9.1 首版功能

- 收入、支出和转账记账
- 流水新增、编辑和删除
- 首页月度统计、今日统计、本周统计和最近流水
- 流水列表、搜索和筛选
- 收支趋势条形图和分类饼图
- 月度账单和年度汇总
- 收支分类管理
- 账户列表、新增和编辑，以及资产、负债和子类型管理
- 本地草稿
- 基础数据导出

### 9.2 后续功能

- 余额调整
- 借入和借出
- 代付和待收款
- 报销和退款关联
- 图片凭证
- 自定义标签
- 多币种及汇率换算
- 周期记账和预算提醒

余额、借贷、代付、报销和退款之间存在较复杂的账务关系，建议在首版基础收支模型稳定后再逐步上线。

## 10. 验收重点

- 首页、流水、图表和账单中的同一统计口径结果一致。
- 新增、修改或删除流水后，账户余额和相关统计同步更新。
- 转账不会同时增加收入和支出。
- 退款和报销不会造成收入虚增。
- 停用分类或账户后，历史流水仍能正常展示。
- 所有一级类型及子类型只接受合法组合，切换类型后不会保存不适用的条件字段。
- 资产账户不能设置负初始余额，负债账户不能设置正初始余额。
- 信用消费、退款和还款后，当前余额与动态计算的欠款保持一致。
- 已有流水的账户不能修改一级类型、账户性质和初始余额。
- 默认账户重复初始化后，账户数量和 `systemKey` 保持不变。
- 现金券默认不计入净资产，信用账户默认作为负债计入净资产。
- 记账过程中刷新或误触返回时，可以恢复未提交的草稿。
- 移动端常见屏幕尺寸下，底部操作区不被浏览器工具栏或安全区域遮挡。
