# 个人资料

入口：我的 → 个人资料（`/profile/user`）。依次显示头像、昵称、用户名，每行进入独立编辑页；列表返回“我的”，编辑页返回资料列表，均不显示底部 Tabbar。

- 昵称与用户名：进入页面获取最新资料并回填；去除首尾空白后允许 1–50 个 Unicode 码点，不额外限制字符种类。空白、超长、未修改、保存中禁用提交。成功提示并返回，失败保留输入。
- 头像：选图即上传并保存；支持 JPG、PNG、WebP，非空且不超过 `5 * 1024 * 1024` 字节。上传期间禁止重复选择，成功留在当前页展示新头像，失败保持原头像；同一文件可以再次选择。不提供裁剪、清除或恢复默认操作。
- 无头像或加载失败时显示应用默认头像。保存后将完整用户资料写回认证 store，同步更新“我的”；退出登录后迟到响应不得写回。
- 页面资料加载失败提供重试；系统默认用户展示不可修改提示并禁用按钮。

## 接口

接口受 Bearer 访问令牌保护，用户身份仅取令牌 ID，沿用 `/api` 前缀和统一响应包装。返回 `User`，序列化排除密码。

| 接口 | 请求 | data |
| --- | --- | --- |
| `GET /user/me` | 无 | 当前用户 |
| `PATCH /user/me` | `{ nickname?: string, username?: string }` | 更新后的用户 |
| `POST /user/me/avatar` | multipart 单文件，字段 `file` | 更新后的用户 |

文本至少提供一个字段，拒绝 null、错误类型和额外字段。用户名必须唯一，包括数据库并发唯一冲突；提交原值不写库。不存在、已删除、已禁用及系统默认用户均不可保存。

头像同时校验 MIME 与真实文件类型，按确认类型规范扩展名，复用附件存储配置；URL 不超过 255 字符。上传后再保存资料，数据库失败时原头像保持有效。历史文件沿用附件保留方式。

旧 `PATCH /user` 保留兼容。本次复用既有字段，无数据库迁移或新增环境变量。
